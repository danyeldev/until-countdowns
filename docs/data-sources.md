# Data sources and refresh policy

Reviewed September 14, 2026. The source registry in `src/lib/ingest/sources/index.ts` is the executable inventory. Public pages read the normalized database; they do not call upstream APIs during rendering. Provider names, links and attribution come from `public.sources` and each event's source URL.

## What changed

- **Formula 1 coverage:** `f1calendar` adds Grand Prix and sprint start times using the [F1Calendar repository](https://github.com/sportstimes/f1). It needs no API key or subscription. Its JSON files are covered by the repository's [MIT license](https://github.com/sportstimes/f1/blob/main/LICENSE); the full notice is retained in [licenses/f1calendar-MIT.txt](licenses/f1calendar-MIT.txt).
- **Safer TV schedules:** TVMaze error objects and empty schedules fail the ingestion unit instead of completing an empty pass that could mark existing premieres stale. Impossible dates and timestamps with no UTC offset are rejected. A blank `TVMAZE_MIN_WEIGHT` now preserves the default instead of turning off the popularity filter.
- **Verified holiday access:** [OpenHolidays' official FAQ](https://www.openholidaysapi.org/en/faq/) explicitly confirms free commercial use and an ODbL data license. The previous adapter note that this was unverified has been corrected.
- **Upcoming means upcoming:** the accompanying catalog migration removes elapsed start times from browse/search results, featured events and related lists, and aligns counts and series selection. Today's all-day events remain visible; imprecise events remain until their stated period expires. Published past event URLs remain available.
- **Astronomy owns changing dates:** season and meteor-shower series use computed occurrences. The correction migration repairs existing autogenerated fixed-date copies, preserves IDs where possible and redirects superseded URLs to computed events. Independently sourced, cancelled and unpublished entries remain untouched.

The dispatcher selects sources using their registered cadence and saved state. Partial passes resume from their checkpoint rather than waiting a full cadence; active leases and backoff are respected. LL2 retains a six-hour refresh separately from its daily staleness tolerance. Source failures must propagate to the runner; a provider outage must never masquerade as a valid empty catalog.

### Useful free providers already retained

- [TVMaze](https://www.tvmaze.com/api) allows public API use under CC BY-SA with attribution and documents at least 20 requests per 10 seconds. The adapter uses one daily request, preserves real broadcast time zones and writes its own descriptions.
- [Launch Library 2](https://thespacedevs.com/llapi) provides its database free at up to 15 requests per hour. The adapter checks its quota endpoint and keeps the cursor when quota is exhausted. `LL2_API_TOKEN` is optional; there is no automatic paid upgrade.
- [OpenHolidays](https://www.openholidaysapi.org/en/faq/) provides an ODbL calendar overlay with documented public sources. Offline `date-holidays` remains the broad baseline.
- [endoflife.date](https://endoflife.date/docs/api/v1/) provides a consolidated lifecycle API, avoiding separate vendor scrapers. Its adapter validates the envelope and plausible product count before accepting a pass.
- [confs.tech's conference-data](https://github.com/tech-conferences/conference-data) supplies MIT-licensed structured conference dates. The adapter merges cross-topic duplicates and uses the raw GitHub host with a mirror fallback.
- [MusicBrainz's API rate policy](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting) requires request pacing and a meaningful User-Agent. `INGEST_USER_AGENT` should identify this installation and a working contact.

## Formula 1 details

The adapter reads `_db/f1/{year}.json` for the current and next calendar years. A read-only check on September 14, 2026 found **23 race weekends** in the current season and no next-season file yet. The race dates were checked against the [official 2026 Formula 1 calendar](https://www.formula1.com/en/racing/2026). Four recorded race weekends are included as deterministic test fixtures.

- Only `gp` and `sprint` sessions produce countdowns; practice and qualifying sessions are not added.
- An exact UTC session retains its circuit's IANA timezone. Las Vegas therefore appears on Saturday locally even though the stored instant is Sunday UTC.
- A date without a time remains an all-day event. Missing, malformed, impossible or out-of-season dates are discarded; no noon/midnight start is invented.
- IDs use season, upstream race slug and session. Round renumbering and date changes retain the same source identity.
- Unknown circuits retain their published UTC instant but receive no guessed country or location metadata.
- A missing next-season file is normal. A current-season 404, malformed envelope, empty race list, or wholly unrecognizable schedule fails the unit. Removed races are handled by the existing stale-record process; the provider has no cancellation-status field, so absence is not labeled an explicit cancellation.
- The community schedule is attributed as F1Calendar; it is not presented as an official Formula 1 feed. Descriptions are generated from schedule facts and contain no copied upstream prose or photographs.

### Alternatives evaluated

| Candidate | Decision |
| --- | --- |
| [Jolpica F1](https://github.com/jolpica/jolpica-f1/blob/main/TERMS.md) | Its current terms make free data CC BY-NC-SA and require contact for commercial use. F1Calendar offers the required schedule coverage without that restriction |
| [TMDB](https://developer.themoviedb.org/docs/faq) | The free API is for non-commercial projects; commercial use requires a separate license. Keep the existing TVMaze/Wikimedia feeds instead of adding a hidden dependency on a commercial agreement |
| More holiday aggregators | Existing offline holidays plus OpenHolidays already provide broad coverage; another duplicate feed adds request cost without a clear coverage gain |
| Additional sportstimes calendars | The repository includes other championships, but each needs its own field/identity/timezone review. They are not enabled by the Formula 1 adapter |

## Running and verifying

Apply `supabase/migrations/20260914211022_f1calendar_source.sql` through the normal database migration workflow **before enabling this code in production**. It inserts only the F1Calendar source row and attribution. The migration was generated locally; this rebuild does not apply it to a remote database or ingest live data.

`supabase/migrations/20260914212035_upcoming_catalog.sql` updates the existing catalog RPCs and statistics with the shared upcoming policy. It preserves the public view's columns and existing RPC signatures for rolling deployments.

`supabase/migrations/20260914213148_astronomy_series_correction.sql` seeds the twelve astronomy series' metadata and repairs existing generated occurrences using offline calculations for 2026–2041. Its recorded calculations do not seed unrelated events into an empty catalog. The recurring astronomy adapter handles later refreshes.

With local configuration in place, inspect the registry or preview normalization:

```sh
npm run ingest -- --list
npm run ingest -- --source=f1calendar --dry-run
```

Run the deterministic adapter checks without network access:

```sh
npx vitest run tests/ingest/f1calendar.test.ts tests/ingest/tvmaze.test.ts tests/ingest/openholidays.test.ts
```

With Docker running, verify the catalog migrations and regression cases against an isolated PostgreSQL 17 instance:

```sh
node scripts/verify-catalog-sql.mjs
```

The verifier creates its own temporary container, exposes no host ports, mounts no project files, uses no remote database credentials and removes the container afterward. It applies catalog migrations, excluding the storage-service bucket migration. Conflicting legacy astronomy fixtures are inserted before their correction migration to test the actual data repair. It also checks search relevance, time boundaries, pagination, related/featured/series selection, counts and maintenance permissions.

Before adding any provider, record its actual access conditions, a sample payload and stable identity scheme. Prefer structured published dates, retain the original source link, preserve date precision, and test empty/error envelopes as well as valid results. A service being public or free does not imply that its images can be reused; the separate image-license pipeline remains authoritative.
